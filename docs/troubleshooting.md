# Troubleshooting

- **Need a log:** start the game with `--log` (for example `.\Game.exe --log` in PowerShell, from the game folder; pass it to `appx-host.exe` or `appx-native-host.exe` instead when the launcher starts one of them, and `appx-native-host.exe` writes its own lines and the game's into the same log). The log is `appx-portable.log` beside the executable, and the two previous runs are kept as `appx-portable.1.log` and `appx-portable.2.log`. Its first lines name the appx-portable version and the package it found. `--trace` logs every Windows Runtime class the game activates; `--diagnostics` adds crash details and checks the heap for damage as the game runs (slower). Both imply `--log`.
- **The installer reports a missing file:** check that the package is the complete `.appx` or `.appxbundle` (or a complete extraction, with `AppxManifest.xml`), and that each VCLibs `.appx` or folder you give has the DLLs listed in [manual installation](manual-install.md#2-get-the-visual-c-runtime).
- **The game fails to start or crashes after loading:** check the log. appx-portable decodes percent-encoded file names itself at startup, so the game folder must be writable; installing with `installappx.py` avoids the problem.
- **Windows 8/8.1 says the app can only run in an app container:** Windows 8/8.1 refuse to start a Store executable or VCLibs DLL marked for an app container outside a package. On those versions the installer creates `Game.desktop.exe` beside the original with only that flag cleared, clears it in the game folder's VCLibs DLLs, and points the launcher at the desktop copy. Pass `--desktop-copy` to do the same on another Windows version. Gameplay on Windows 8/8.1 itself remains unverified.
- **Check which version is installed:** right-click `appxportable.dll` and open **Properties → Details**. **Product version** names the release and the commit it was built from. All appx-portable DLLs in a game folder should show the same version.
